# 数据字典

## 0. 本篇结构说明

v1 真实运行的系统只依赖两类数据：① `clean_supply_chain.csv`（业务数值数据，供工具层查询）② `knowledge_base/*.md`（方法论知识，供 RAG 检索）。本篇先给出这两类 v1 真实数据的完整字段字典，再给出评测数据的字段字典，最后在附录列出 02/03 文档中提到的"目标态概念模型"字段字典（供 v2 参考，当前未落地）。

## 1. v1 业务数据：`clean_supply_chain.csv`（100 行 × 24 列）

来源：真实公开供应链数据集（快消/美妆行业，100 个 SKU 样本），经 `scripts/clean_data.py` 清洗规范化，原始文件见 `data/real_supply_chain.csv`。

### ⚠️ 数据质量说明：两个"提前期"字段不能合并

`lead_times_days`（报价提前期）与 `lead_time_days`（实际提前期）字段名高度相似，容易被误认为同义重复列，但清洗脚本做了逐行一致性校验后发现**两者近乎零相关（r≈-0.003）**，必须分别保留，不能静默合并成一列。这是本项目在真实数据清洗中发现的典型陷阱；`clean_data.py` 对所有同义候选列都采用"先断言一致，不一致就报错阻断"的方式，而不是"直接合并"，防止同类问题再次静默发生。

## 2. v1 知识数据：`knowledge_base` chunk 字段（RAG 检索单元）

每篇 `knowledge_base/*.md` 被 `chunker.py` 按 `##` 标题切成 chunk，字段如下：

| 字段 | 含义 | 示例 |
|---|---|---|
| id | chunk 唯一编号（`来源文件-序号`） | business_rules.md-2 |
| source | 来源文件名 | business_rules.md |
| doc_title | 文档标题（H1） | 库存策略与补货规则 |
| section_path | 完整来源路径（文档标题 > 小节标题） | 库存策略与补货规则 > 1. 安全库存 |
| title | 小节标题 | 1. 安全库存 |
| content | 切片正文（含 `[来源: ...]` 前缀） | — |

## 3. 评测数据字典

| 文件 | 字段 | 含义 |
|---|---|---|
| `data/eval_cases.json` | id / type / query / grounding / verify / expected | 评测用例：编号 / 类型（rag,tool,hybrid） / 问题 / 标注依据（语义锚点） / 验证方法 / 期望结果 |
| `data/eval_results.json` | intent_pred / intent_ok / gold / recall3 / e2e / top3 | 评测结果：预测意图 / 路由是否正确 / 标注 gold chunk id / 是否召回进 top3 / 端到端是否正确 / 实际召回的 top3 列表 |
