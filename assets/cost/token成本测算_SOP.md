# Token 成本测算方法论 · 第一性原理 SOP

> 适用：模型产商品上架定价、资源包设计、智能网关综合成本预测、投资与经营风险测算
> 配套交互工具：收益分析系列 4 个计算器（2×2 矩阵）+ 1 个补充版（核销率 / 三场景 / 龙卷风）

---

## 0. 为什么要从第一性原理写这份 SOP

多数团队的 token 成本测算是「抄厂商计费规则」：火山怎么算我怎么填，金山云怎么报我怎么记。这种做法在单模型、单厂商时勉强可用，一旦遇到 **多厂商聚合、组合包、智能网关路由、资源包核销** 就会失准——本作品集里「武汉上架表原定价因忽略结构出现负毛利」就是典型后果。

第一性原理的做法是：**不依赖任何一家厂商的规则，只从「模型服务到底是什么」这一个最基本的事实出发，推导出自变量、公式与风险框架。** 推导出的体系天然可迁移——换厂商、换模态、从单模型到网关，都只是同一套公理的不同实例化。

本文档与「收益分析」系列 4 个交互式计算器是同一方法论的「文字版」与「工具版」：SOP 负责讲清"为什么"，计算器负责把"为什么"变成可拖拽、可决策的产品。
---

## 1. 第一性原理：从「模型服务的本质」出发

**P0 ｜ 模型服务 = 以 token 为统一计量单位的算力服务**
模型对外交付的不是「一台机器」，而是「按 token 计费的算力」。因此一切成本与收入最终都锚定在 **token 数量** 这一个本位上。→ 记账本位统一为 **百万 token（M token）**，消除各厂商单位混乱。

**P1 ｜ 任何一次请求的成本 = 实际消耗的 token 数量 × 该 token 的供货单价**
> cost = Σ (tokenᵢ × priceᵢ)

这是成本唯一不变的底层定义。后面所有公式都是它的展开，不是新规则。

**P2 ｜ token 不是同质的：按「流向」与「是否命中缓存」被差异化定价**
供应方对三类 token 报不同的价：
- 输入（未命中缓存）：按全价 `P_in`
- 输入（命中缓存）：按便宜价 `P_cache`（通常 ≈ P_in 的 1/5~1/2）
- 输出（模型生成）：按最贵价 `P_out`（通常 ≈ P_in 的 2~4 倍）

**P3 ｜ 一次请求的总 token 是守恒的，但「花在哪一类」决定成本**
设一次请求总 token 为 1（归一），它必然被分到上述三类，比例分别为 `r_in / r_cache / r_out`，且
> **r_in + r_cache + r_out = 1**

成本不是由「平均单价」决定，而是由「最贵那类占多少」决定——这是后续所有毛利设计的支点。

**P4 ｜ 平台不是单一模型，而是路由层**
一个请求可能被路由到不同模型（能力/成本/可用性权衡），还可能是多模型组合。因此总成本 = 各模型成本按**真实流量占比**加权：
> 路由分布 `π_k`，且 **Σ π_k = 1**（流量守恒）

对"固定组合包"，路由是既定搭配，此时用 **消耗当量系数 k**（每个模型折算成"基准模型 token 当量"的乘数）更直观；对"动态网关"，用实时流量分布 π 更真实。两者是同一 P4 的两种实例化。

**P5 ｜ 售价是「按已售额度」收，成本是「按实际消耗」付**
资源包 / Token Plan 先卖出额度，用户未必用完。只有被**核销（实际消耗）**的部分才产生供货成本。所以存在一个业务折损系数：
> **核销率** = 已售额度中真正被消耗的比例（0~1）

---

### 第一性原理 → 变量映射（一眼看清每个变量从哪来）

```
P0  统一计量单位          →  记账本位：百万 token
P1  成本=消耗×单价        →  供货单价 P_in / P_cache / P_out
P2  差异化定价            →  三结构拆分（输入/缓存/输出）
P3  token 守恒            →  比例约束 r_in+r_cache+r_out = 1
P4  路由层加权            →  路由分布 π（Σπ=1）/ 组合包系数 k（消耗当量倍数）
P5  售/耗错配            →  核销率（业务折损系数）
```

## 2. 由原理直接推导的公式体系

| 层级 | 公式 | 来自哪条公理 |
|---|---|---|
| 单模型三结构成本 | `C_k = r_in·P_in + r_cache·P_cache + r_out·P_out`（元/百万 token） | P1 + P2 + P3 |
| 组合包成本（固定搭配） | `C_pkg = Σ (k_i · C_i)`，`k_i`=各模型消耗当量倍数（coeff） | P4（固定组合特例） |
| 网关综合单位成本（动态） | `C_gw = Σ π_k · C_k` | P4 |
| 有效单位成本 | `C_eff = 核销率 × C_gw` | P5 |
| 套餐利润（元） | `利润 = 售价 − C_eff × 套餐规格(M)` | P1 + P5 |

**约束（源自守恒，不是经验值）**
- `r_in + r_cache + r_out = 1`（一次请求的 token 被完整划分）
- `Σ π_k = 1`（流量被完整划分）

### 口径约定
- **毛利率**（SOP 主口径）=（售价 − 成本）/ 售价。
- **利润率**（计算器主口径）=（售价 − 成本）/ 成本 = 成本利润率/加价率。
- 两者换算：`毛利率 = 利润率 ÷ (1 + 利润率)`；`利润率 = 毛利率 ÷ (1 − 毛利率)`。
- 计算器风险分级基于**利润率**：<5% 高风险、5%~15% 中风险、≥15% 低风险。

## 3. 跨模态折算：为什么必须有一道「折算层」

P0 要求所有成本锚定 token，但网关实际吞的是文本/语音/视频/图片。**必须先统一折算成 token，才能喂进同一套成本模型。** 折算公式源自物理/分词规则：

| 模态 | 折算规则（示例，随厂商而定） |
|---|---|
| 文本 | 按分词 → token 数 |
| 语音输入 | 1 秒 ≈ 6.25 输入 token |
| 语音输出（合成） | 1 秒 ≈ 25 输出 token（方向不同，单价不同） |
| 视频 | token = (入+出时长) × 宽 × 高 × 帧率 / 1024 |
| 图片 | 按张折算为固定 token（如 ¥0.22/张 折算） |

## 4. 风险仪表盘：三类场景 + 敏感性（第一性原理视角）

P1~P5 推导出的 C_gw / 毛利，其输入（r、π、P、核销率）**全是估计值**。第一性原理要求：凡估计，必测「估计错了会怎样」。

- **三类场景** = 对假设参数（r、π、核销率）分三档「坏程度」扰动，看商品是否仍在安全区间：
  - 基准：最可能相信的假设（只定预算，不代表安全）
  - 压力：正常业务波动范围内的轻微不利
  - 极端：对平台最不利的压测（输出比例拉高、用户集中调贵模型、核销率近 100%、缓存命中下降、上游优惠减少）
- **敏感性测试** = 系统性逐个扰动变量，量化每个变量对毛利的边际影响，定位「让商品开始亏损的边界」。核心问题不是「能赚多少」，而是「**哪个变量一变，就开始亏**」。通常 `r_out`、核销率斜率最陡，优先监控。
- **三条线**（定价时必备）：
  - 盈亏平衡线：毛利 = 0 → 售价 = C_eff
  - 目标毛利线：售价 = C_eff / (1 − 目标毛利率)
  - 风险线：毛利低于经营下限时的售价阈值

> 交叉验证：同一售价 4，基准毛利 35.3%、压力 −1.4%、极端 −40.7%——证明「商品安不安全不看基准盈不盈利，看压力/极端是否仍可接受」。

### 计算器如何把"风险"做成可交互
本作品集 4 个计算器把上述方法论拆成两层可操作工具：
1. **收益临界分析**（对应"三条线"）：对每一个套餐，实时解出"输出比例推到多少开始破盈亏平衡"（即各模型的 p10/be10 临界曲线），并给出 利润率 + 风险等级。
2. **各模型盈亏（耗尽额度）**（对应"极端场景"）：把"用户只用某一模型耗尽全部额度"作为该模型的最不利压测，直接暴露哪个模型在哪个套餐下会亏——这是把 P5 核销率=100% 的极端情形具象化。

## 5. 配套计算器：2×2 矩阵与使用映射

"收益分析"系列 4 个计算器是本文档的方法论实例化，构成一张 **2×2 矩阵**——两个维度正好对应 P3（三结构比例如何设）与 P4（单模型还是路由层）：

|  | **单模型** | **多模型 / 组合包**（P4：路由/组合） |
|---|---|---|
| **缓存命中率模式**（设缓存命中率+输出比例，输入比例自动算） | 收益分析_缓存命中率模式.html | 收益分析_多模型_缓存命中率模式.html |
| **自由调节模式**（三比例 r_in/r_cache/r_out 自由设，强制 Σ=1） | 收益分析_自由调节模式.html | 收益分析_多模型_自由调节模式.html |

### 5.1 两个"模式"在讲什么（对应 P3）
- **缓存命中率模式**：你给运营侧能拿到的「缓存命中率」和想探查的「输出比例」，输入未命中比例 `r_in = 1 − r_cache − r_out` 由守恒自动算出。适合"知道缓存水平、想看输出失控边界"的研讨。
- **自由调节模式**：三比例全放开手拖，适合做敏感性扫描（对应第 4 节敏感性测试）。

### 5.2 单模型 vs 多模型在讲什么
- **单模型**：直接计算 `C_k = r_in·P_in + r_cache·P_cache + r_out·P_out`，给出该模型下各套餐的利润率/风险/收益临界。
- **多模型（组合包）**：每个模型带两个关键量——
  - `coeff`（消耗当量倍数 **k**，如 DeepSeek=1、MiniMax=3、GLM=8）——把该模型折算成基准模型的 token 当量；
  - `modelWeights`（路由/使用分布 **π**，Σ=1）。
  
  综合单位成本即 `C_gw = Σ π_k · (k_k · C_k)`。计算器会输出"加权供货价"与各模型的盈亏柱，直观看到路由权重一调、整体成本怎么变。

### 5.3 计算器通用输出（决策闭环）
- **套餐包选择**：预填真实套餐（如 10M/50M/100M/5亿 Token 资源包、文本模型基础/进阶/专业/加量套餐）与厂商单价（DeepSeek / MiniMax / GLM 等三结构报价）。
- **加权供货价**：多模型下实时汇总成"基准当量单价"。
- **各模型盈亏分析**：若用户只用某模型耗尽全部额度，该套餐是否盈利——极端压测。
- **收益临界分析**：每个套餐的风险等级（高/中/低）+ 利润率，并可用搜索/筛选快速定位"哪些套餐在当前假设下已亏"。

## 6. SOP：十步落地（从原理到可执行）

> 每一步都标了它服务的公理，便于审计与交接。

| 步 | 动作 | 对应公理 | 关键要求 |
|---|---|---|---|
| 1 | 定记账本位为「百万 token」 | P0 | 全团队统一，禁止混用不同单位 |
| 2 | 采集各模型三结构供货单价 `P_in/P_cache/P_out` | P1,P2 | 取最新报价，记录来源与有效期 |
| 3 | 设定用量结构假设 `r_in/r_cache/r_out`（Σ=1） | P3 | **必须基于真实业务压测，禁止拍脑袋** |
| 4 | 定路由分布 `π`（网关/组合包）或消耗当量 `k`（组合包） | P4 | π 来自真实流量；k 来自实测消耗当量 |
| 5 | 算单模型 `C_k` 与组合/网关 `C_gw` | P1~P4 | 校验 Σr=1、Σπ=1 |
| 6 | 乘核销率得 `C_eff` | P5 | 资源包/Plan 必做；第 5 个计算器已含核销率滑块，前 4 个以"耗尽额度"作极端档 |
| 7 | 定售价，算利润率/毛利率，做市场对标 | P1,P5 | 对标同业，留安全垫 |
| 8 | 收益临界 + 各模型盈亏压测（即极端场景） | 风险公理 | 用计算器"各模型盈亏（耗尽额度）"逐模型验 |
| 9 | 敏感性分析，定位首要监控变量 | 风险公理 | 通常 `r_out`、核销率最陡，优先监控 |
| 10 | 画三条线，设预警阈值，用真实流量持续校准 | P3,P4,P5 | 上线后回流数据反哺步骤 3/4 |

**两条铁律（源自守恒公理，不可破）**
1. 先算「三结构 + π/k」再定价，禁止用单一平均单价。
2. `r`、`π`、核销率必须真实压测校准——武汉「原定价」负毛利正是忽略它们的代价。
