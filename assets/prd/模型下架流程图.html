模型生命周期管理

模型下架执行主流程

系统/信息步骤 关键操作 不可逆 / 警示 时间线节点

准备与确认

管理员发起下架请求，系统协助校验影响面
  • 运营后台「已上架模型列表」点击下架，进入四步弹窗
  • 选择下架场景：合规整改 / 性能迭代 / 平台运营调整 / 模型能力异常
  • 填写生效日期（默认当天，不可早于当天）、内部原因、用户通知内容
  • 系统拉取该模型下所有生效/未生效订单，按（企业 ID, 模型 ID）去重生成影响记录
状态锁定：禁止新购 / 续订 / 扩容

预告与通知

下架单创建后 5 分钟内完成预告通知下发
  • 模型状态置为 SOON_OFFLINE（即将下架）
  • 前端模型卡片置灰 + [即将下架] 标签 + 倒计时
  • 站内信 + 邮件触达个人/企业管理员，含四要素：模型、时间、受影响订单、核心规则
通知时效目标：创建后 5 分钟内

存量保护期

下架操作日 → 生效日期，存量租户按原规则继续使用
  • 保护期内再次发送“最后机会”提醒
  • 期间仍禁止新购 / 续订 / 扩容
  • 不同场景建议缓停期：合规整改 0–7 天 / 性能迭代 14–30 天 / 运营调整 7–14 天 / 能力异常 0–3 天
时间线：缓停期 = 下架操作日 → 生效日期 23:59:59
生效日期到达 · 时间线分界点

正式下架

模型停止调用，进入 OFFLINE 终态
  • 模型状态置为 OFFLINE，卡片显示 [已下架]
  • API 网关对该模型调用统一返回 410 MODEL_RETIRED
  • 计费停止点生效，下架后的失败调用不计费
  • 调用记录、账单、关联政府券核销记录打包归档，模型记录不可物理删除
不可逆终态：须重新走完整上架流程才能恢复

权益处理

单模型包 / 组合包分别计算补偿
  • 单模型包：未消耗权益 = 未使用 Token ÷ 总 Token × 订单实付金额，券面额 100% 折算、四舍五入到元
  • 组合包：先判继续售卖（包内可用模型 ≥ 原模型数 60%）
  • 组合包 L0：包内有同能力标签模型 → 仅通知，不发券
  • 组合包 L1：核心能力受损 → 通知 + 按依赖度 r 发放补偿券（封顶实付 30%）
  • 免费试用账户 / 已过期订单 / 赠送额度不补偿
补偿券：平台通用券，90 天有效，不可提现/找零/转赠

售后与归档

用户主动申请 + 审计留痕
  • 下架生效日起 30 天内用户可主动发起权益补偿申请，逾期系统自动发放代金券
  • 下架操作接入统一审计日志（操作人 / 时间 / IP / 内容）
  • 历史订单、通知记录、补偿发放记录可对账追溯
补偿处理有效期：下架生效日起 30 天

去重规则

  • 唯一键：(企业 ID, 模型 ID)
  • 通知：每（企业 × 模型）1 次
  • 补偿券：每（企业 × 模型）1 张

错误码

正式下架后 API 统一返回：

410 MODEL_RETIRED
该模型已下架，请在平台自行选择其他模型或 Token Plan。

量化目标

  • 下架流程 100% 线上闭环
  • 权益处理触达率 ≥ 99%
  • 410 错误码一致率 100%
