2. 需求背景与目标

2.1 业务背景（痛点 + 价值）

  • 痛点 1 · 逐条勾选不可行：按量付费产品按天出账单，单月可达数十条，逐条勾选开票成本高、易错。
  • 痛点 2 · 企业多账户开票割裂：企业存在主账户与多个子账户，管理员需跨账户统一开票，且需按账户拆分，原有能力缺失。
  • 痛点 3 · 开票资格与状态边界不清：充值未消费、体验金/虚拟货币抵扣部分能否开票、已开票部分是否重复计入等规则无统一口径，易引发客诉。
  • 痛点 4 · 金额计算不透明：用户无法理解「可开票金额」为何小于「订单总额」，缺乏可下钻的计算明细。
  • 业务价值：降低开票操作成本、透明金额计算口径、支撑企业多账户合规开票、减少开票类客诉。

2.2 产品目标（SMART）

  1. 一次性支付订单「买完即可开票」，按量付费订单「次月 X 号后」可发起开票。
  2. 跨账期按量付费订单按账期独立开票，互不影响。
  3. 企业空间支持跨账户「合并为一发票 / 按账户分别开票」。
  4. 可开票金额计算精度到「分」，分以下舍弃，金额勾稽误差为 0。
  5. 订单/账单状态判定由统一函数计算（零手填），判定准确率 100%。
  6. 支持多个订单合并开一张发票。

2.3 用户角色矩阵

角色 空间 核心诉求 权限
ToC 个人用户 个人空间 按月汇总一次性提交开票 仅本人消费记录
ToB 企业管理员 企业空间 跨账户合并/拆分开票、查账期结算明细 全部子账户消费记录
子账户（企业成员） 企业空间 查看本人账单 只读，无独立开票权限

5. 用户故事

  • 作为 ToC 个人用户，我希望按「月周期」一次性汇总整月按量付费账单并提交开票，以便免去逐条勾选的繁琐。
  • 作为 ToB 企业管理员，我希望跨账户选择消费记录并「合并 / 拆分」开票，以便统一合规开票并按需拆分给各账户核算。
  • 作为任意用户，我希望查看「可开票金额」的计算明细并下钻到账单级，以便理解为何部分金额不可开、避免误解。
  • 作为任意用户，我希望订单与账单的开票状态有清晰、统一的名词界定，以便准确判断当前是否可开。
  • 作为企业管理员，我希望将多个订单合并开一张发票，以便减少发票张数与报销流转成本。

6. 业务规则与状态机

6.1 发票关联规则

1 个账期结算单元 = 1 张发票。

6.2 支付方式与账期结算单元

支付方式 说明 账期结算单元
一次性支付（购买 Token 资源包） 买完即可开票 仅 1 个账期结算单元
后付（按量计费） 按天出账单，单月约 30 条；订单跨月持续存在（如横跨 5/6/7 月），无天然结束点 账期结算单元 = 某订单 × 某自然月账期

6.3 跨周期两种开票模式

  • 按月开票模式：选定一个账期（月份），列表每行即一个「账期结算单元」，无需额外处理。
  • 按订单开票模式：按自然月整月出账，每行对应该订单在某月的消费汇总，以「月度结算记录」展示；订单号仅用于信息展示，不作为实际开票字段，实际开票按该订单的账期。订单号后加「共 X 期」气泡，悬停显示："该订单持续出账，系统中共有 N 个账期结算单元，按账期分别独立开票，互不影响"。

6.4 日期筛选语义（关键规则）

  • 后付费按自然月整月出账，日期用于圈定账期所在月份，不代表按天筛选账单。
  • 日期筛选的作用是帮用户定位账期结算单元；搜索命中判断对象 = 「账期结算单元所在自然月」与「搜索区间」是否重叠，不是逐条账单比日期。
  • 只要账期与搜索区间有任何重叠，该账期结算单元即被搜出，展示完整整月金额与状态，不会因搜索区间仅覆盖部分月份而拆成「半个月」。

示例（搜索 5.15–6.29）：

  • 5 月账期（5.1–5.31）：与搜索区间重叠（5.15–5.31）→ 命中，展示整个 5 月账期金额与状态；
  • 6 月账期（6.1–6.30）：与搜索区间重叠（6.1–6.29）→ 命中，展示整个 6 月账期；
  • 7 月账期：完全不重叠 → 不命中。

6.5 开票资格（评审结论 · 问题3-(1)）

  1. 充值开票：充值金额需完成实际消费并结算后，方可申请开票；未消费的充值金额不支持直接开票。
  2. 体验金 / 虚拟货币抵扣部分不可开票。
  3. 已开过票的部分不会重复出现在可开票范围内。
  4. 开票金额按选中订单的实付金额汇总计算，金额计算到分，分以下部分舍弃。
  5. 按量付费产品：开通后按实际资源消耗量产生后付费账单，于次月 X 号后生成上月月账单，即可发起开票申请。

6.6 订单级状态（5 值，优先级自上而下，命中即返回）

优先级 值 判定条件 说明
1 未出账 订单会持续产生新账单 == true 且 订单.账期 == 当前自然月 持续出账订单，当前账期未结束，账单未最终生成
2 可开票 可开票金额 == 订单总额 全额可开
3 部分可开票 0 < 可开票金额 < 订单总额 一部分可开、一部分不可开（原因见明细）
4 已开票 可开票金额 == 0 且 历史已开票金额 > 0 已开过发票，不是不能开，是不需再开
5 不可开票 可开票金额 == 0 且 历史已开票金额 == 0 全部为体验金 / 虚拟货币等本身不合规部分

6.7 账单级状态（3 值）

值 判定条件 说明
可开票 账本类型 == 真实货币 且 未被开过票 该条账单本身可开
已开票 账本类型 == 真实货币 且 历史上已开过票 汇总到订单级时计入历史已开票金额
账本类型不可开票 账本类型 == 体验金 / 虚拟货币 汇总到订单级时计入本月不可开票金额

6.8 可开票金额公式

可开票金额（大字橙色）
  = 总计消费可开票金额        （截至当前时点的总计消费可开票金额）
  − 历史已开票金额            （此前已申请并开具的金额；可下钻明细）
  − 本月不可开票金额          （含体验金/虚拟货币抵扣 + 后付费当月未结算部分，次月X号后可开；可下钻明细）

6.9 多订单合并开票（评审结论 · 问题1）

  • 经与业务负责人确认，允许多个订单合并开一张发票。
  • 提交时：所选订单的可开票金额汇总为单张发票金额；企业空间可叠加「合并 / 拆分」模式选择。

7. 详细功能说明

7.1 开具发票主流程（个人 / 企业）

  • 前置条件：用户已登录且具备开票权限（子账户无权限，见 12 安全）。
  • 主流程：
    1. 选择空间（个人 / 企业）。
    2. [企业] 选择账户范围 + 拆分模式（合并 / 拆分）。
    3. 选择开票方式（按订单 / 按月周期）。
    4. 按月周期：选周期 → 系统汇总本周期 → 订单列表默认全选；按订单：填筛选条件 → 勾选目标订单。
    5. 可查看「计算明细弹窗」与下钻账单明细页。
    6. 底部汇总栏展示已选账户数 / 订单数 / 金额。
    7. 提交：个人「申请开票」；企业合并「申请开票」/ 拆分「提交拆分开票申请」。
  • 异常流程：可开票金额 = 0 时禁止提交并提示原因；子账户进入开票页提示「无开票权限」。
  • 后置条件：生成发票申请工单，进入「已开具列表」流转。

7.2 账户范围与拆分（企业空间）

  • 账户范围卡片：拆分模式单选（合并为一张 / 按账户分别开票）+ 账户下拉选择器（默认收起）。
  • 合并模式：所有选中账户消费汇总为一张发票；拆分模式：按账户分别生成发票。

7.3 周期选择器与汇总卡片（按周期模式）

  • 当前月：禁用灰显，文案「本月未出账」，不可点击（提示用户当月按量计费账单未出账）。
  • 近 3 月：可点击快捷选择。
  • 更早月份：下拉框选择第 4–12 月（评审结论 · 问题6）。
  • 本周期汇总卡片：大字金额 + 共 X 笔订单 / X 笔可开票 + 「查看计算明细」入口。

7.4 订单详情页（评审结论 · 问题4 / 问题5）

  • 入口：订单表格「详情」列。
  • 交互约束：点击详情跳转至独立页面（替换主内容区，非弹窗），带返回按钮；展示订单关联下所有账单信息，不可选中、不可操作，仅查看。
  • 账单明细表格：账单编号 / 账单月 / 账本类型 / 账户类型 / 实付金额 / 开票状态；分页展示。
  • 一次性订单显示「该订单为一次性结算，无逐笔账单明细」。
  • 跨账期后付费订单显示「共 X 期」说明气泡。
  • 月账单场景下「查看详情」展示该状态下的全部账单，不可选择、仅展示。

7.5 计算明细弹窗与公式下钻页

  • 弹窗（居中模态）：标题「可开票金额」，三项拆解 + 各自说明气泡（总计 / 历史已开 / 本月不可开）+ 关闭。
  • 下钻页（替换主内容区，带返回）：
  • 点击「历史已开票金额 → 查看明细」：展示历史已开票关联账单列表（无则提示「本周期没有相关记录」），汇总表含订单号。
  • 点击「本月不可开票金额 → 查看明细」：展示本月不可开票关联账单列表（无则提示同上）。

7.6 提交与回执

  • 提交后生成申请，回执展示申请编号、所选范围、金额、拆分模式；企业拆分模式逐账户回执。

8. 交互流程

主流程（个人空间）

进入页面 → 选择开票方式（按订单 / 按月周期）
  ├─ 按月周期：选周期 → 系统汇总 → 订单列表默认全选 → 查看计算明细弹窗 → 下钻账单明细页
  └─ 按订单：筛选（关键字/日期区间/状态）→ 勾选目标订单
→ 底部汇总栏（已选订单数 / 已选金额）→ 提交「申请开票」

主流程（企业空间）

进入页面 → 选择账户范围 + 合并/拆分模式
  → 选择开票方式（同上）
  → 底部汇总栏（已选账户数 / 订单数 / 金额）
  → 提交合并「申请开票」或拆分「提交拆分开票申请」

异常流程

  • 可开票金额 = 0 → 提交按钮禁用 + 文案「无可开票金额」；
  • 子账户访问开票页 → 提示「无开票权限」，不展示操作区；
  • 跨账期订单点击详情 → 独立页展示「共 X 期」，逐期账单只读。

10. 边界场景

类别 场景 处理
异常 可开票金额 = 0 提交禁用，提示原因（已全开 / 全为体验金）
异常 体验金 / 虚拟货币订单 全额计入「不可开票」，状态「不可开票」
异常 子账户访问开票 无权限，仅展示本人账单，不开放操作
异常 后付费当月未结算 本月不可开票，次月 X 号后转入可开
极限 跨多账期（如横跨 5/6/7 月） 展示「共 X 期」，按账期独立开票互不影响
极限 单月 30+ 账单 订单详情页分页（10 条/页）
极限 超大金额精度 计算到分，分以下舍弃，勾稽误差 0
极限 十二月周期展示 本月灰显禁点 + 近 3 月快捷 + 更早下拉（第 4–12 月）
并发 重复提交 幂等：同一批选定 + 同金额仅生成一张申请工单
并发 已开票部分再次开票 已开票不重复计入可开票范围，防重复开

11. 验收标准（可量化）

编号 标准 量化条件
AC1 状态判定准确率 订单级 5 值 + 账单级 3 值由统一函数计算，零手填，准确率 100%
AC2 金额精度 计算到分，分以下舍弃，勾稽误差 = 0（可开票 = 总计 − 历史已开 − 本月不可开）
AC3 跨账期搜索 搜索 5.15–6.29 须命中 5 月、6 月账期，不命中 7 月，且展示整月金额
AC4 多订单合并 多个订单可合并生成一张发票，金额 = 各单可开票金额之和
AC5 详情页跳转 点击详情跳转独立页面、带返回、账单只读不可操作
AC6 十二月周期 本月灰显禁点，近 3 月可点，更早月份下拉可选
AC7 计算明细 弹窗三项拆解 + 下钻页数据与原列表同源一致
AC8 分页 订单列表 / 账单明细均 10 条/页，分页正确
AC9 企业拆分 合并 / 拆分模式提交后分别生成 1 张 / 多张发票
AC10 权限 子账户无开票操作权限，仅本人账单可见
AC11 重复提交 同批次同金额重复点击仅生成 1 张申请工单（幂等）
AC12 开票资格 未消费充值、体验金/虚拟货币、已开票部分均不进入可开票范围

12. 非功能需求

  • 性能：订单列表首屏 P95 ≤ 2s；计算明细弹窗响应 ≤ 1s。
  • 安全隐私：服务端强鉴权，按账号过滤；子账户不可越权查看他人账单；发票抬头/税号加密存储。
  • 可靠：开票申请幂等，防止重复开票；账期结算单元计算异常可重试。
  • 兼容：个人 / 企业双空间自适应；桌面端优先，适配主流分辨率。
  • 可观测：关键操作埋点（见 13）；状态计算异常可审计。
