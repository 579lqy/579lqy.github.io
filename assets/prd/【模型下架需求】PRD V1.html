2. 需求背景与目标

2.1 业务背景

平台模型供给随合规要求、性能迭代、运营策略调整、模型能力异常等原因需要下架。在缺乏标准化下架流程时，存在以下痛点：

  • 无下架规则设计，下架动作随意，缺乏业务决策与范围确认，易误伤在途订单；
  • 存量用户权益（已购 Token 包 / 组合套餐）无统一补偿机制，引发客诉与纠纷；
  • 前端状态、通知触达、API 调用拒绝未统一，用户在下架后仍收到不一致体验；
  • 计费停止点、历史归档口径不清，财务与审计无法追溯。

2.2 业务价值

  • 标准化：将下架收敛为可审计、可回放、可追责的六阶段流程；
  • 权益保护：以「平台通用券 / 额度转移」等非退款形式保障存量用户剩余权益，兼顾合规与体验；
  • 风险可控：前端预告 + 站内信 / 邮件 + API 410 错误码三位一体，降低客诉与合规风险；
  • 可追溯：保留模型记录与历史归档，不可逆操作留痕。

2.3 产品目标（SMART）

目标 量化指标
下架流程线上化 下架单创建到生效通知 100% 线上闭环，无线下人工协调
存量权益覆盖率 受影响租户的权益处理触达率 ≥ 99%

6. 业务规则与状态机

6.1 模型生命周期状态机

       创建下架单
ONLINE ──────────────► SOON_OFFLINE（即将下架 / 预告期）
   ▲                      │  缓停期（下架操作日 → 生效日期）
   │                      │
   │   (本期不支持)       ▼  生效日期 23:59:59 后
SUSPENDED ◄───────   OFFLINE（已下架，终态，不可恢复）
(预留，不实现)
状态 枚举 说明
已上架 ONLINE 正常可购可调用
即将下架 SOON_OFFLINE 已创建下架单、预告期内，禁止新购 / 续订 / 扩容
已下架 OFFLINE 终态，不可恢复，须走完整上架流程重新上线
已停用 SUSPENDED 预留枚举，本期不实现（设计意图：临时停用后可恢复）

6.2 下架场景与建议缓停期

场景 枚举 说明 建议缓停期
S1 合规整改 COMPLIANCE_RECTIFY 监管要求或平台自查发现合规问题 0–7 天
S2 性能迭代 PERFORMANCE_ITERATION 性能升级 / 架构调整，旧版汰换 14–30 天
S3 平台运营调整 PLATFORM_ADJUST 运营策略变化、模型线优化 7–14 天
S4 模型能力异常 MODEL_ANOMALY 输出质量严重下降或功能异常 0–3 天

6.3 订单范围与去重规则

  • 下架单生成时，系统自动拉取该模型 ID 下的所有生效 / 未生效订单，来源包含：单模型订购、组合包内嵌、API 调用。
  • 去重唯一键：(企业 ID, 模型 ID)。
  • 通知：每（企业 × 模型）1 次，通知内列出所有关联订单；
  • 补偿券：每（企业 × 模型）1 张，面额 = 剩余累加额。
  • 典型去重：企业同时购买单模型订购包与含该模型的组合包时，仅生成 1 条影响记录、1 次通知、1 张券。

6.4 状态锁定

下架单生成后即时生效：禁止新购、续订、扩容；仅保留存量调用与存量保护期内的正常使用。

6.5 通知规则

  • 触达对象：个人 → 个人账号；企业 → 企业管理员。
  • 渠道：站内信 + 邮件。
  • 邮件四要素（预告期与存量保护期均须包含）：①明确下架模型 ②明确下架时间 ③明确受影响订单 ④核心规则（不提供模型 / 数据迁移，剩余权益折算为平台通用券，自行在新模型中重新调用）。存量保护期提醒额外强调"最后机会"。

6.6 权益补偿规则

6.6.1 单模型包

  • 未消耗权益价值 = 未使用 Token 数 ÷ 总 Token 数 × 订单实付金额。
  • 券面额 = 未消耗权益 × 100%，精确到元，四舍五入。
  • 券类型：平台通用券（不可提现、不可找零）。
  • 有效期：发放后 90 天有效，过期自动报废，视为放弃权益。
  • 订单状态改为「下架结算完成」。

6.6.2 组合包（Token Plane）

  • 下架模型立即停用。
  • 继续售卖判定：包内可用模型总数 ≥ 原模型数 × 60% → 继续售卖。
  • 继续售卖：不整体退款、不整体重算、剩余 Token 总额度不减少、不退款不折算、有效期不变；其他模型不受影响继续计费，订单保持有效继续扣费；仅当核心能力明显受损时按等级发券。
  • 停止售卖：未消耗权益价值 = 未使用标准 Token ÷ 总标准 Token × 订单实付金额。
  • 影响等级：
等级 判断标准 处理方式
L0 无补偿 包内有同能力标签模型可用 仅通知
L1 有补偿 包内无同能力模型（核心能力受损） 通知 + 发券
  • 判定逻辑：IF 下架模型.标签 ∈ 组合包内其他模型的标签列表 → L0；ELSE → L1。
  • L1 权益计算：依赖度 r = 该用户套餐当前计费周期内该模型消耗标准 Token ÷ 同期消耗标准 Token 总量；退款补偿 = 套餐实付金额 × r × 套餐剩余有效期占比（封顶实付金额 30%）。

6.6.3 券通用约束

  • 不可提现、不可找零、不可转赠其他企业或个人；
  • 不可叠加政府券、不可叠加其他活动；
  • 平台券使用优先级最高；
  • 发放时间：模型下架后自动发放；
  • 过期作废：下架日期 + 120 天未使用自动作废，不延期、不补发；
  • 到账通知：站内信；
  • 免费试用账户不补偿。

6.7 计费与错误码

  • 计费停止点：以模型正式下架时间为停止计费点；下架后的失败调用不计费。
  • 后付费：按下架时刻账单截止金额计算。
  • 订购：按实付金额折算，赠送额度不兑现不折现，已过期订单不补偿。
  • API 错误码（正式下架后统一返回）：
{
  "code": 410,
  "error": "MODEL_RETIRED",
  "message": "该模型已下架，请在平台自行选择其他模型或 Token Plan。"
}

6.8 补偿处理有效期

下架生效日期起 30 天内，用户可主动发起权益补偿申请；逾期系统自动发放代金券（见用户空间交互）。

7. 详细功能说明

7.1 阶段一：下架确认（业务决策与范围）

  • 前置条件：操作人为平台运营管理员，目标模型状态为 ONLINE。
  • 主流程：
    1. 在「已上架模型列表」点击目标模型「下架」；
    2. 弹窗 Step1 选择下架场景（S1–S4）；
    3. Step2 填写下架生效日期（默认当天，不可早于当天）、内部原因（仅后台可见）、用户通知内容；
    4. 系统拉取订单范围，按 (企业 ID, 模型 ID) 去重生成影响记录；
    5. 创建下架单，模型状态置为 SOON_OFFLINE，触发状态锁定。
  • 异常流程：未选场景 / 必填项为空 → 禁用「下一步」；生效日期早于当天 → 校验拦截。
  • 后置条件：下架单与影响记录落库；模型禁止新购 / 续订 / 扩容。

7.2 阶段二：下架预告（通知与预期管理）

  • 前置条件：下架单已创建，状态 SOON_OFFLINE。
  • 主流程：
    1. 前端模型卡片置灰 + [即将下架] 标签 + 倒计时；
    2. 触发站内信 + 邮件通知（个人 / 企业管理员），内容含四要素。
  • 异常流程：通知渠道失败 → 重试队列 + 监控告警，不影响状态流转。
  • 后置条件：预告期内用户可见即将下架标识与倒计时。

7.3 阶段三：存量保护期

  • 主流程：存量租户按原规则使用至正式下架日；保护期内再次发送提醒（强调"最后机会"）。
  • 边界：保护期不开放新购 / 续订 / 扩容。

7.4 阶段四：正式下架

  • 前置条件：到达下架生效日期 23:59:59。
  • 主流程：
    1. 模型停止调用，状态置 OFFLINE；
    2. 前端卡片 [已下架]；
    3. API 网关对该模型调用统一返回 410 MODEL_RETIRED；
    4. 数据归档（调用记录、账单、关联政府券核销记录打包），模型记录不可物理删除；
    5. 计费停止点生效，失败调用不计费。
  • 异常流程：网关拦截延迟 → 旧调用仍可能短暂成功，需对账补偿（不计费）。
  • 后置条件：模型不可被搜索 / 浏览 / 订购；历史可查。

7.5 阶段五：权益处理（核心）

  • 单模型包：按 6.6.1 计算未消耗权益 → 生成平台通用券（100% 折算、四舍五入、90 天有效）→ 订单标记「下架结算完成」。
  • 组合包：先判继续售卖（≥60%）→ 继续售卖走 L0/L1 判定与依赖度补偿；停止售卖走 6.6.2 独立折算。
  • 异常：已过期订单 / 免费试用账户 → 不补偿；赠送额度不折现。

7.6 阶段六：售后（券发放与约束）

  • 主流程：下架后自动发放券至券中心；站内信通知到账；用户（企业需手动领取）在券中心使用。
  • 约束：见 6.6.3；下架日 +120 天未使用自动作废。

7.7 用户空间权益补偿交互（P1）

  • 入口：Token 包状态为「已停止」或「部分模型已下架」时出现「处理权益」按钮。
  • 补偿方案：
  • 转移额度：将剩余 Token 按换算比例转移至其他有效模型 Token 包；选择目标模型时系统按同供应商 / 同能力标签推荐（标注推荐与换算比例），提供 API 文档链接与 model_id 替换提示；
  • 发放代金券：按剩余价值折算为平台通用券。
  • 交互约束：补偿方案一经确认立即执行，不可撤销、不可重新选择。

8. 交互流程

8.1 主流程（管理员下架）

1. 选择模型（已上架模型列表 → 下架）
   ↓
2. 填写下架信息（场景 / 生效日期 / 内部原因 / 用户通知）
   ↓
3. 预览影响范围（受影响用户数 / 有效 Token 包 / 缓停期）+ 二次确认
   ├─ 确认项：永久不可恢复 / 存量可用至生效日 23:59:59 / 生效日后调用拒绝 / 不可撤销
   ↓
4. 完成下架 + 通知（状态置 OFFLINE / 发通知 / 归档 / 停止计费）

8.2 用户权益补偿流程

用户空间（Token 包 / Token Plane）
   ↓ 状态变为「已停止 / 部分模型已下架」
点击「处理权益」
   ↓
选择补偿方案（转移额度 / 发放代金券）
   ├─ 转移额度 → 选择目标模型（系统推荐同标签）→ 确认
   └─ 发放代金券 → 确认
   ↓
确认后不可更改 → 执行 → 状态更新为「已补偿」

8.3 异常流程（关键分支）

  • 去重冲突：企业同时单购 + 组合包 → 仅 1 条影响记录 / 1 次通知 / 1 张券；
  • 通知失败：进入重试队列，状态流转不阻塞；
  • 网关拦截延迟：下架瞬间旧调用成功 → 不计费，对账兜底。

10. 边界场景

类型 场景 处理
异常 已过期订单 不补偿
异常 免费试用账户 不补偿
异常 赠送额度 不兑现、不折现
极限 组合包可用模型数 = 原模型数 × 60%（临界） 判为继续售卖
极限 组合包无同能力标签模型 判 L1，发券（依赖度计算，封顶 30%）
极限 模型恰好 0 订购用户 跳过通知发送，仍走归档
极限 下架生效日 23:59:59 边界调用 计入存量；23:59:59 后调用返回 410
并发 同一模型重复创建下架单 状态锁定后拒绝第二次，提示"已存在下架单"
并发 去重窗口内企业同时单购 + 组合包 仅生成 1 条影响记录
并发 网关拦截延迟导致下架瞬间旧调用成功 不计费，对账兜底
逆向 撤销下架 本期不支持；如需恢复须走完整上架流程
逆向 用户未在 30 天 / 120 天内处理 逾期自动发放代金券 / 券自动作废

12. 非功能需求

  • 性能：下架单创建至影响预览渲染 P95 ≤ 2s；通知批量下发支持 ≥ 1 万租户 / 批次。
  • 安全隐私：内部原因仅运营后台可见，不向用户侧泄露；券发放、用户剩余权益等数据按租户隔离，服务端强鉴权。
  • 可靠性：通知失败重试 ≥ 3 次；下架操作为幂等（同一模型重复请求拒绝）；归档异步执行不阻塞主流程。
  • 兼容性：运营后台兼容主流浏览器（Chrome / Edge / Safari 近两版本）；用户空间适配移动端 H5。
  • 可观测：下架关键节点埋点（见第 13 章）；异常操作接入审计日志与告警。
