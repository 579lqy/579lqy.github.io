# Token工场模型下架 — 术语表

---

## 一、术语定义

|术语|定义|
|---|---|
|**模型下架**|平台运营管理员将已上架模型从Token工场移除的操作。下架后模型不可被新用户搜索/浏览/订购|
|**下架生效日期**|下架操作时指定的日期。已购用户可继续调用至该日期的 23:59:59，之后API网关拒绝调用|
|**缓停期**|下架操作日 → 下架生效日期之间的时间段，供已购用户消耗剩余Token额度|
|**永久下架**|模型状态变为"已下架\(OFFLINE\)"，为终态，不可恢复。如需重新上线，须走完整上架流程（新建模型\+审核\+上架）|
|**已下架（OFFLINE）**|模型状态枚举值，终态。与"已停用\(SUSPENDED\)"区别：后者可恢复|
|**已停用（SUSPENDED）**|预留状态枚举值，本期不实现。设计意图：允许临时停用后恢复上架|
|**存量Token包**|下架前用户已订购且尚未耗尽/未过期的Token资源包|
|**Token Plane**|多模型组合套餐包（如文本模型组合包），包含多个模型 \+ **固定Token总额度（套餐内模型共用）** \+ 固定有效期，按套售卖|
|**权益补偿**|模型下架后，用户因无法继续消费剩余权益所获得的非退款形式补偿|
|**补偿处理有效期**|下架生效日期起 30 天内，用户可主动发起权益补偿申请|
|**模型价值权重**|Token Plane 中单个模型占套餐总价值的比例，用于折算下架模型的补偿份额|
|**核心能力受损（L1）**|Token Plane 内下架模型无同能力标签的可用替代模型，视为套餐核心能力受损，需发放补偿券|
|**额度转移**|Token资源包用户将下架模型剩余 Token 额度按换算比例转移至其他有效模型 Token 包|

# 二、未尽事项 / 后续建议

1. **下架生效日期到期后的自动拦截**：需与API网关团队对齐，确认网关侧增加模型状态检查的时间点和技术方案。

2. **操作审计日志**：下架操作应接入平台统一的审计日志系统（操作人、时间、IP、操作内容）。

3. **代金券中心对接**：需确认代金券发放接口、使用规则、过期策略是否已具备。
